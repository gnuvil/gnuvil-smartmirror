# MMM-GnuvilBus

경기버스정보(GBIS)의 정류소별 버스 도착정보 목록을 2분마다 한 번 조회합니다. 화면은 마지막 응답 시각을 기준으로 30초마다 남은 시간을 다시 계산하며, 이 계산은 API를 추가로 호출하지 않습니다. 시간이 0분 이하로 계산되면 `곧 도착`이라고 표시합니다. 실제 도착은 교통 상황에 따라 달라질 수 있습니다. 현재 도착 예정 시간이 있는 노선만 가까운 순서대로 표시하며, 버스 번호는 고정하고 긴 행선지만 가로로 움직여 끝까지 볼 수 있습니다. API 호출과 응답 정규화는 `node_helper.js` 쪽에서 수행합니다.

## 설정

`config/config.js`의 `MMM-GnuvilBus` 항목에 실제 값을 입력합니다.

```js
config: {
  stationId: "228000346",
  stationMobileNo: "29555",
  routes: null, // 모든 노선
  walkMinutes: null,
  subtractMinutes: 5,
  updateInterval: 120000,
  staleAfter: 300000
}
```

`stationMobileNo`는 승객용 정류소번호입니다. 현재 기준은 **외대.모현빌라(29555), 서울 방면**이고 `stationId` 228000346은 2026-10-29 GBIS 통합검색 응답에서 확인했습니다. 서버는 이 값을 이용해 정류소 조회 단계를 생략합니다.

이전 기준이던 학교 안 외국어대학교(29561, `228001371`)는 1005·1117·1150·1303번의 **출발지**입니다. GBIS는 버스가 출발하기 전에는 도착 시간을 주지 않아 이 노선들이 빈 시간으로 와서 1500-2번만 보였습니다. 길 건너 모현지석묘입구(29554)는 이 노선들이 학교로 들어오는 방향입니다. 외대.모현빌라에서도 종점 출발 노선은 출발한 뒤에야 시간이 나옵니다.

`stationId`를 비우면 [정류소명/번호 목록조회](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusStation)에서 `stationMobileNo`와 번호가 일치하는 ID를 찾아 사용합니다. 이 조회는 도착정보와 **별도의 API 활용신청**이 필요합니다(지금 키는 도착정보만 등록되어 있음).

`subtractMinutes`를 지정하면 도착 예정 시간에서 그만큼 빼서 "지금 나가면 몇 분 여유가 있는지"로 표시합니다. 빼고 나서 0분이면 `지금 출발`, 음수면 지금 나가도 못 타는 버스이므로 그 노선의 다음 버스를 보여 주거나 숨깁니다. 기본값 0은 기존과 같이 도착 예정 시간 그대로이고, 0분 이하면 `곧 도착`입니다. `routes: null`은 API가 반환한 모든 노선을 표시합니다. 같은 노선이 양방향 항목으로 반환되면 `routeDestName`을 표시하므로 1500-2번의 에버랜드행과 사당행도 구분됩니다. GBIS가 한쪽 방향의 도착정보를 반환하지 않으면 그 방향은 표시되지 않습니다. 특정 노선만 표시하려면 `routes`에 `{ routeName, routeId? }` 항목을 넣을 수 있습니다. `walkMinutes`는 실제 평균 도보시간을 확인한 뒤 정수로 지정할 수 있습니다. `null`이면 출발 안내 문구를 표시하지 않습니다.

[공공데이터포털의 이 API 안내](https://www.data.go.kr/data/15080346/openapi.do)에 표시된 개발계정 신청 가능 트래픽은 하루 1,000회입니다. 서버 한 대를 2분 간격으로 24시간 계속 실행하면 약 720회이며, 현재 설정은 숫자 `stationId`를 사용하므로 정류소 조회 요청도 하지 않습니다. 같은 키로 데스크탑과 Raspberry Pi를 동시에 실행하거나 다른 프로그램에서도 사용하면 호출량이 합산될 수 있습니다. 계정에 실제로 승인된 한도는 공공데이터포털의 활용신청 현황에서 확인합니다.

GBIS API 키는 **MagicMirror를 실행하는 서버의** `GBIS_API_KEY` 환경 변수에 넣습니다. 공공데이터포털의 디코딩 키와 인코딩 키를 모두 사용할 수 있습니다. 키는 저장소, `config.js`, 브라우저로 전달하지 않습니다. 정류소·키 중 하나라도 없으면 네트워크 요청을 시작하지 않고 설정 오류를 표시합니다.

`stationId`를 비워 두면 **정류소명/번호 목록조회**와 **버스 도착정보 목록조회** 두 API를 사용합니다. HTTP 403이 `station lookup`에서 발생하면 공공데이터포털에서 정류소 조회 API의 활용신청·승인 상태를 확인하세요. `arrival lookup`에서 발생하면 버스 도착정보 API의 이용 권한을 확인하세요. 이미 확인된 숫자 `stationId`를 `config.js`에 설정하면 정류소 조회 호출은 생략됩니다. 정확한 ID를 검증하지 않은 상태에서 임의 값을 넣지 마세요.

사용한 API는 [경기버스정보의 버스 도착정보 목록조회](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusArrivalStation)입니다. `format=json`, `stationId`, `serviceKey`를 보내고 `response.msgBody.busArrivalList`의 `predictTime1/2`, `predictTimeSec1/2`, `locationNo1/2`를 정규화합니다.

## 검증

이 디렉터리에서 `node --test`를 실행합니다. 실제 GBIS 호출은 키와 정류소가 준비된 뒤 확인해야 합니다.
